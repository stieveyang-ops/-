## 一、中文路径下的 `BLOCKED` 问题（已于 2026-10-13 修复）

作品所在路径含中文（`黑客松`、`可运行作品`）。工具会把本次运行的配置写入 `prospective_runs\<TargetID>\prospective_search_config.yml`，其中包含作品的绝对路径（含中文，UTF-8 编码）；AiZynthFinder 4.4.1 按进程区域编码读取该 YAML，在中文 Windows（cp936/GBK）下抛出：

```
UnicodeDecodeError: 'gbk' codec can't decode byte 0xae in position 398
```

于是工具按硬停止规则写出 `prospective_blocker.json`，界面显示 `BLOCKED`。这不是数据或模型问题，也不是复制造成的。

**修复方式**：三个启动入口现在都会在启动 Python 之前设置 `PYTHONUTF8=1`，该变量被 GUI、评分器及 AiZynthFinder 子进程逐级继承，文本文件以 UTF-8 读取。不涉及模型、配置或任何冻结科研文件的改动。

| 入口 | 修复前 | 修复后 |
|---|---|---|
| `launch_gui.cmd` | 未设置 | 已加入 `set "PYTHONUTF8=1"` |
| `launch_gui.ps1` | 未设置 | 已加入 `$env:PYTHONUTF8 = "1"` |
| `prospective_difficulty_tool\run_prospective_scoring.ps1` | 未设置 | 已加入 `$env:PYTHONUTF8 = "1"` |
| `启动_可运行作品.cmd` | 已设置 | 不变 |

修复前的原文件备份在 `local_deployment\pre_20261013_fix_launch_gui.cmd`、`pre_20261013_fix_launch_gui.ps1`、`pre_20261013_fix_run_prospective_scoring.ps1`。

因此现在双击 `launch_gui.cmd` 或 `启动_可运行作品.cmd` 均可直接运行，命令行方式也不再需要手工设置环境变量。若将作品放在纯英文路径（如 `D:\aizynth_work\`），该问题不会出现。
