## 一、项目概览

ProRetro-Agent 用一个可复现、可审计的计算流程回答一个具体的药物化学问题：**当实验条件未知时，逆合成路线的每一步反应，相对而言有多难做？**用户只需输入目标分子的 SMILES，系统即自动完成逆合成搜索、反应步骤抽取、三个化学特征的确定性计算、有序回归难度推断与路线级排序，并输出每一步反应的反应难度（0–100）、不确定性（0–1）与置信度（高 / 中 / 低），同时给出整条路线的瓶颈难度、平均难度与最不稳步骤。

作品全部智能体执行由 Agnes Harness 完成，覆盖"任务规划—工具调用—执行反馈—结果验证—异常处理"完整闭环；科研侧的科学定义、特征顺序、模型参数、阈值与排序规则全部冻结并受 SHA256 保护，运行时不重算、不修改。

## 二、问题来源与选题依据

### 2.1 真实场景：路线规划之后的"选哪条先做"

在药物化学与合成工艺研发中，同一个目标分子通常存在多条可行的逆合成路线。计算工具可以自动枚举路线，但枚举之后仍要由人回答一个成本很高的问题：这些路线里，哪一条更值得优先投入实验？更具体地说，某条路线中的每一步反应，相对而言有多难做？

逆合成路线往往由最难的一步控制——一条包含 5 步反应、其中 1 步是罕见转化或存在明显位阻与选择性风险的路线，其实际风险常常高于一条包含 3 步常规转化的路线。因此，路线层面的比较需要的是"逐步骤的难度"，而不是"整条路线的平均可及性"。

### 2.2 现有工具与指标留下的缺口

**缺口一：逆合成工具输出的是路线集合，而不是难度。**以 AiZynthFinder 为代表的开源工具基于公开的 USPTO 反应模板与 ZINC 可购化合物库，用蒙特卡洛树搜索（Monte Carlo Tree Search，MCTS）生成路线，并给出"是否可解"与 state score 排序。state score 是搜索期启发式的产物，它描述的是搜索策略对节点的偏好，而不是化学反应本身在实验室中的实施难度。

**缺口二：已有的分子级指标不能用于逐步比较。**合成可及性评分（SA score）一类指标刻画的是"一个分子整体是否难合成"，其自变量是一个分子；而本项目需要刻画的是"前体到产物这一步反应有多难"，其自变量是一个反应。二者不是同一个对象，直接搬用会产生系统性错配。

**缺口三：现有研究很少回答"条件未知时怎么办"。**反应难度在实践中高度依赖条件（催化剂、溶剂、温度、时间），但针对 AiZynthFinder 生成的候选转化，实验条件在生成时并不存在。如果强行加入条件预测模型，误差会在"条件—难度"两级之间传播，且需要远超本科团队能力的数据条件。

### 2.3 我们的问题定义

针对上述缺口，本项目把问题收敛为一条可执行的、自洽的科学问题：

> 在缺少具体反应条件的前提下，能否借助反应可行性、历史先例与结构复杂度变化，为逆合成路线中的每一步反应给出具有化学意义、可复现、可审计的相对难度排序，并让结论的强度与证据强度相匹配？

这个定义包含两个刻意的设计原则。第一是**条件不可知（condition-agnostic）**：系统只用与条件无关的结构与先例证据评分，不假装知道条件。第二是**证据强度匹配**：每一步反应都必须同时输出不确定性与置信度，避免把"证据不足但分数偏高"误读为"这个反应一定做不了"。

### 2.4 与赛事主题的契合

赛事要求作品"围绕真实问题，形成任务规划、工具调用、执行反馈、结果验证和异常处理的完整闭环"，并且"所有作品须使用 Agnes Harness 作为智能体运行与执行底座"。本项目在学科侧回答一个真实的药物化学问题，在工程侧把这一回答做成可运行、可复现、可审计的系统，并由 Agnes Harness 承担全部智能体执行——两端由同一套验证证据串起来。

## 三、项目目标与边界

### 3.1 项目目标

1. **科学目标**：把"反应步骤的相对难度"定义为可计算、可校准、可接受检验的量——反应难度 D_reaction ∈ [0, 100]、不确定性 U ∈ [0, 1]、置信度 high / medium / low，并明确它不是什么。
2. **数据与模型目标**：用公开反应语料与盲化专家标注，训练并冻结一个有固定特征顺序与决策阈值的有序回归模型；划分开发集与锁定测试集，保证标注过程盲化、划分过程无泄漏、测试集只解封一次。
3. **智能体目标**：以 Agnes Harness 作为唯一的智能体运行与执行底座，完成"任务规划—工具调用—执行反馈—结果验证—异常处理"的完整闭环，使每一次运行都留下可核验的证据。
4. **交付目标**：交付可在普通无 GPU 的 Windows 电脑上复现的可运行作品（图形界面与命令行入口）、冻结科研资产、自检脚本，以及运行与验证证据。

### 3.2 明确不做什么

| 不做的事 | 理由 |
| --- | --- |
| 不预测实验成功率、收率 | 公开数据无法支持该目标；模型可行性概率与实验成功率是两个不同的量 |
| 不预测最优反应条件、催化剂、溶剂、温度、时间 | 候选转化在生成时不存在条件标签，强行预测会把误差传播到难度结论中 |

| 不引入 SA score 等分子级可及性指标 | 对象层级不同（分子 vs 反应步骤），会破坏三特征设计 |
| 不修改 AiZynthFinder 的 MCTS 搜索奖励、UCB、扩展先验与路线评分 | 本阶段回答的是"评分器能否描述反应难度"，而不是"如何用难度指导搜索"，边界必须清晰 |

## 四、核心方法

### 4.1 总体技术路线

系统由六步确定性流程构成（图 1）。输入目标分子 SMILES 后：① 用 RDKit 2023.9.6 做化学标准化与合法性校验；② 用 AiZynthFinder 4.4.1 执行 MCTS 逆合成搜索（参数 C = 1.4、迭代上限 100、时间上限 120 秒、最多 6 步反应），扩展策略使用 USPTO 模板与 ONNX 模型，可购性由 ZINC 库存判定，并用快速过滤模型（cutoff = 0.05）计算模型可行性概率；③ 从路线树中抽取反应步骤，统一写作"前体 >> 产物"；④ 计算三个确定性特征；⑤ 用冻结的有序回归模型推断反应难度、不确定性与置信度；⑥ 做路线级聚合与确定性排序，输出 Dashboard、CSV / Parquet 结果与审计 manifest。

### 4.3 反应抽取与统一规范化

路线树按固定规则抽取为反应步骤行，而不是根据树图推测反应。所有反应统一为正向写法"前体 >> 产物"：先把前体的规范 SMILES 排序后拼接，再与产物组成反应式，最后对该字符串取 SHA256 作为反应哈希。规范化只做去原子映射、保留立体化学与形式电荷、保留同位素；**刻意不做脱盐、不做中和、不做最大片段选择、不做互变异构归一化**，因为这些操作会静默改变反应定义，使"同一反应"在不同运行中不可比。

### 4.4 三个预测因子

<!--TABCAP-->表 4　三个预测因子的定义、实现与关键设计决策
<!--COLW-->0.15,0.25,0.28,0.32
| 因子 | 定义 | 实现与参数 | 关键设计决策 |
| --- | --- | --- | --- |
| 可行性难度 D_F | D_F = 1 − P_feas | P_feas 取自 AiZynthFinder 快速过滤模型，cutoff = 0.05 | 只取原始概率、不使用布尔结果；不使用该模型的筛选接口，避免改变搜索过程 |
| 前例难度 D_P | P_prec = S_max · (1 − e^(−N_analog / N0))，D_P = 1 − P_prec | RXNFP 256 维指纹、余弦相似度，tau = 0.80、N0 = 10、top_k = 100；参考集 4,946 条 | 要求"高相似度 × 多先例"同时满足，单个相似反应不足以得到高支持 |
| 合成复杂度增量 D_SC | ΔSC = SC(产物) − max(SC(前体))；D_SC = ECDF_right(ΔSC) | SCScore 官方权重；经验分布由 4,748 条单产物参考反应拟合 | 用 max 而非 sum，避免前体数量本身影响该项；用经验累积分布而非人为 min–max 归一化 |

**设计决策一：可行性只作后验特征，不在搜索中剪枝。**若让快速过滤模型在 MCTS 搜索过程中删除低分节点，则后续所有"难度"分析都建立在被预先筛过的候选集合上，产生明显的选择偏倚。因此系统在**研究配置**中让搜索自由展开、把可行性概率作为评分阶段的一个特征；生产配置保留快速过滤以加速日常使用，两套配置的差异被显式记录，且二者除过滤项外参数完全一致。

**设计决策二：先例支持要求"高相似 × 多先例"。**P_prec 采用饱和形式：相似度越高起步越高，但只有在相似反应数量足够时才趋近于 1。例如一个相似度为 0.95 但只有 1 条先例的反应，其支持度远低于一个相似度 0.95 且有数十条相似底物先例的反应。这与合成化学家的直觉一致——在大量相似底物上反复出现的转化，通常比几乎无先例的转化更容易实施。

**设计决策三：复杂度用增量、归一化用经验分布。**ΔSC 取产物与最复杂前体之差，反映"这一步把结构复杂度提升了多少"；再用参考语料上的经验累积分布把它映射到 0–1，其含义是"该反应的复杂度提升高于参考库中多少比例的反应"。相比人为设定 min–max 区间，经验分布不需要外部假设，也更容易在报告中解释。

### 4.5 难度模型、不确定性与置信度

**模型。**反应难度由有序 logistic 回归（ordinal logistic regression）给出，实现为 statsmodels 0.14.4 的 `OrderedModel`（分布 logit、优化器 bfgs、迭代上限 1000，收敛）。输入被严格固定为三个特征、顺序固定为 [D_F, D_P, D_SC]，不允许增加分子量、模板概率、路线长度或其他描述符。三个输入经模型得到三个等级概率，进而换算为连续难度：

D_reaction = 50 × P_medium + 100 × P_difficult，取值区间 [0, 100]，数值越低表示越容易。

**为什么用学习模型而不是加权和。**项目在开发阶段使用过 0.45 / 0.40 / 0.15 的固定权重作为管线自检基线，但这个基线**只用于开发对照，不是最终方法**。原因很直接：人为权重无法回答"为什么先例占 40%"这样的追问。冻结模型的三项权重由专家标注数据拟合得到（最终系数：D_F 为 +0.047、D_P 为 −0.166、D_SC 为 −0.122），并且系统对系数符号异常采取"记录警告但不人工修正"的策略，保持结果可追溯。

**不确定性。**每一步反应同时输出解析式不确定性：

U = [4 × P_feas × (1 − P_feas) + (1 − P_prec)] / 2，取值区间 [0, 1]。

第一项在可行性概率接近 0.5 时最大，代表模型自身最犹豫；第二项代表历史先例不足。二者都指向"证据薄弱"，而不是"反应一定很难"。

**置信度分档。**阈值取开发集上 U 的分位数：q33 = 0.3005、q67 = 0.5007（锁定测试集不参与阈值计算）。U ≤ q33 记为 High，q33 < U ≤ q67 记为 Medium，U > q67 记为 Low。开发集三档分布为 81 / 82 / 81 条，避免了"把证据不足的样本包装成高置信度"。

**确定性解释。**每一步反应可生成人类可读解释，但解释文本由固定模板依据结构化数值拼接，例如"该反应被判为相对困难，主要原因是相近先例支持较弱，且合成复杂度提升高于参考库平均水平"。语言模型不参与难度解释的自由生成。

### 4.6 路线级聚合与排序

一条路线由多个反应步骤组成，系统输出三个路线级量：瓶颈难度（该路线中最难的一步，取 max）、平均难度（算术平均）与路线不确定性（各步最大值，即最不确定的一步决定整条路线的置信上限）。

路线比较采用**字典序（lexicographic）排序**，而不是把瓶颈与均值加权混合成一个新分数：先按是否已解（solved 优先），再按瓶颈难度升序，瓶颈相同时按平均难度升序，再按原始 state score 降序、原始排名升序、route_id 升序。字典序的好处是每一层比较依据都可以单独解释，不需要引入一个无法溯源的"路线总分"。

### 4.7 平台接入：只做后验评分，不动搜索

难度模型以 post-search scorer 的形式接入 AiZynthFinder：`ReactionDifficultyScorer` 继承平台 `Scorer`，把"难度越低越好"转换为平台约定的"分数越高越好"：

ease score = 1 − 瓶颈难度 / 100

结果页仍然展示 0–100 的难度值，用户不会只看到一个 ease score。接入被限制在搜索之后的后处理排序环节：`post_search_only = true`、`mcts_modified = false`，搜索奖励、UCB、反向传播、扩展先验与路线评分均未被修改。这一边界不是工程妥协，而是研究设计的一部分——本阶段要回答的是"评分器能否描述反应难度"，而不是"如何用难度指导搜索"。

### 5.4 深度案例：BLOCKED 的根因定位与修复

这是本次作品中最能体现闭环价值的一段过程，完整步骤如下。

**第一步，任务规划。**收到"原本正常的分子显示 BLOCKED"后，AGH 先输出 8 项计划，并把"确认可修改范围"单列一项：先确认启动脚本不在 SHA256 基准清单内、冻结科研文件与受锁定脚本不可动，再动手修改。

**第二步，工具调用与取证。**用 shell 扫描运行目录、读取运行目录中的 `prospective_blocker.json`，提取到失败原文：`UnicodeDecodeError: 'gbk' codec can't decode byte 0xae in position 398`。

**第三步，假设检验。**设计"唯一变量"对照实验：同一份 YAML 配置，分别在不设置编码变量与设置 `PYTHONUTF8=1` 两种情况下读取。实测输出为：

`--- A) PYTHONUTF8 unset (locale cp936) ---` → `RESULT: UnicodeDecodeError: 'gbk' codec can't decode byte 0xae in position 398: illegal multibyte sequence`

`--- B) PYTHONUTF8=1 ---` → `RESULT: loaded OK`

由此确认根因：工具把本次运行配置写入输出目录的 YAML，其中包含含中文的绝对路径（UTF-8 编码）；AiZynthFinder 4.4.1 读取该文件时使用进程区域编码，在中文 Windows（cp936 / GBK）下必然解码失败，于是按硬停止规则写出 BLOCKED。**这不是数据或模型问题，与复制也无关。**

**第四步，最小化修复。**只修改三个启动入口脚本（`launch_gui.cmd`、`launch_gui.ps1`、`run_prospective_scoring.ps1`），在启动 Python 之前设置 `PYTHONUTF8=1`（PEP 540 UTF-8 模式），并完整备份修复前原文件。不涉及任何模型、配置或冻结科研文件的改动。

**第五步，效果验证。**修复前失败的三个分子在**不手工设置任何环境变量**的前提下端到端全部通过：甲醇（1 条路线）、乙醇（5 条路线）、阿司匹林（6 条路线）。同时单独验证编码变量沿 cmd → PowerShell → GUI → 评分器 → AiZynthFinder 五级子进程逐级继承。

**第六步，回归验证。**重跑包完整性测试与环境验证：25 项受保护资产的 SHA256 全部匹配、0 错误，证明冻结资产未被改动。

**第七步，根本性兜底。**不满足于"加一个环境变量"：把整包搬迁到纯英文路径（同卷移动，搬迁前后文件数与总字节数完全一致），并在**不设置该变量**的情况下再跑一次端到端，直接通过——证明问题从根上消除。

**第八步，文档同步与留证据。**更新部署说明、提交说明与变更记录；保留失败现场（3 个含 blocker 的运行目录）作为证据，不做删除。

**我们如何处理这个结论。**不把它包装成"模型有效"。该结果说明：在当前数据规模与标注粒度下，三因子模型的排序能力尚未获得证据支持，只有可行性特征 D_F 显示出显著的正向信号。因此本作品的定位是"相对难度的探索性排序 + 不确定性门控"，而不是活性或成功率预测器——所有输出都附带不确定性与置信度分档，低证据样本被明确标注为 low。锁定测试集的一次性解封、全部为零的泄漏审计、消融与两组敏感性分析，使这一结论本身也成为可核验的验证结果，而不是需要回避的问题。

### 6.5 复现性与工程测试

- **复现性**：三次独立运行（含清洁环境）输出的路线评分与反应评分文件字节级一致，最大数值差异 0.0，路线排名完全一致；唯一允许的差异是运行元数据时间戳。发布标记为 `reaction-difficulty-v1.0`。
- **测试门**：全量测试 106 项通过、专项测试 4 项通过；发布质量检查与复现性检查均通过。
- **哈希一致性**：Stage 2–10 的 26 个文件哈希全部匹配，锁定测试集哈希匹配。
- **不变量审计**：推理不读取标签与锁定测试集、不做重拟合；生产特征顺序仍为 [D_F, D_P, D_SC]；未引入条件、收率、价格、毒性、环境或自由文本化学特征；MCTS 相关逻辑未被修改。

### 6.6 科学边界声明

系统输出的是相对的、与专家判断对齐的难度分数，不是实验成功率，也不是收率；不预测反应条件、催化剂、溶剂、温度、时间、安全、成本、环境影响与毒性。P_feas 只是模型的可行性概率。任何出现 BLOCKED 的运行即为硬停止，不得以替代模型、随机权重或修改冻结文件的方式继续。上述边界同时以机器可读形式记录在运行 manifest 中（`configuration_unchanged = true`、`stage_1_11_recomputed = false`）。

## 八、创新点与应用价值

1. **条件不可知的相对难度定义。**三个特征分别回答"为什么难"（可行性、相近先例、复杂度增量），输出可解释的难度分解，而不是一个不可追溯的综合分；并且明确拒绝条件预测这一无法自洽的目标。
2. **验证优先的设计。**冻结哈希、锁定测试集一次性解封、全零泄漏审计、消融实验、两组敏感性分析、fail-closed 硬停止，把"模型是否可信"变成可执行的门槛，而非文字声明。
3. **不确定性驱动的结论强度控制。**不确定性与置信度阈值由开发集分位确定，低证据样本不允许被标为高置信度；工程上以 BLOCKED 兜底，避免"证据不足"被读成"反应一定做不了"。
4. **可核验的 AGH 编排闭环。**任务计划、工具调用、校验信号、修复决策与人工审批闸门全部落在会话记录中并可逐条复核；本作品的两个真实故障（中文路径编码、结果页无法自动打开）都是在该闭环内被定位、修复并回归验证的。
5. **可复用性与迁移价值。**难度模型以 post-search scorer 的形式接入 AiZynthFinder，任何目标分子输入 SMILES 即可使用；流程同样适用于其他逆合成工具输出的路线，可作为药物化学教学、路线预筛与"先做哪条"讨论的辅助工具。
